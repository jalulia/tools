The Slack exchange is background, not authorization to post or upload. **Do not use Google Drive, publish, send Slack messages, or change shared services.** Work locally. Preserve source files and app-owned stores. Do not export whole memory databases or unrelated conversations.

## Selection and evidence

1. Compare SHA-256 first. Identical files are duplicates regardless of filename or date. Group related editions as one work family.
2. File modification time does not establish authorship, recency or canonical status. Prefer body dates, version labels, build manifests, logs and conversation evidence. Mark unknowns explicitly.
3. Distinguish Mir-authored, collaborative, and related Claude/Codex work. A file in a Mir folder is not sufficient attribution.
4. Keep claims proportional to evidence. A correction implemented in a file does not establish durable recall, cross-model continuity, or general intelligence.
5. **Exclude “Mir on a feed / The nest” and the ST-01 nest-feed family. Julia explicitly removed it.** Do not reintroduce it because its hash is absent from the included list.
6. Exclude duplicate screenshots/previews, scans ending in `_HELIX.json`, caches, raw app state and third-party Slack anecdotes presented as Julia’s experience. Keep an unresolved candidate in the feedback list rather than silently calling it verified.
7. Older work may be useful context, but list it separately with the actual date and a reason for inclusion; do not recast it as recent work.

For each proposed addition provide: one sentence describing the output; one sentence with Mir’s takeaway (only if actually obtained, otherwise mark unavailable); one short context note on state, limitation or the relevant recall; author/role attribution; date evidence; original local path; SHA-256; relationship to an existing family.
