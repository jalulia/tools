Scopewhat was read · how claims are marked

This document specifies the Mindgut desktop application at build 2.2.58: its runtime, the memory file it keeps, the tools a model can call inside it, and the operating rules for a model attached to the record. It is written for a developer or designer who has not seen any conversation.

The public repository is ten weeks behind the shipped build, and the build ships compiled Python. For anything added after August 2026 the readable evidence is the shipped frontend, the application log, and the data files the runtime writes. Those components are marked accordingly.

No personal information appears here. Example strands are real measurements with their text removed; where words are needed they are synthetic and say so.

Overviewwhat it is · what it is not

A desktop and web application that wraps a language model in a persistent, measured record of the conversation.

The record is a file the user holds, the HELIX. Each turn is converted by deterministic code into two strands in that file; no model is involved. On every turn a fixed selection of past strands is placed in front of the model without the model asking (involuntary recall), and the model can read the record on purpose through tools (voluntary recall). The model's working context is kept to seven exchanges, trimmed to four (PAR respiration).

The persona that speaks is Mir. The underlying model can be switched mid-session across four vendors; the session, history and HELIX continue. app.js · model switcher

Underneath is one piece of arithmetic: every letter is mapped to one of three classes by its position in the alphabet. The three fractions form a phase vector; their variance is σ_B; their difference is balance. These are what the runtime measures, stores, recalls by, and trims by. The author's theory behind it (Paradox Field Dynamics) ships as a 774-strand book inside the app; the arithmetic is described here without the theory. scanner.py:40–70

Conceptsdefined once

2.1Z₃ encoding

Each letter A–Z is numbered 1–26 and reduced to its digital root. The root falls in one of three classes: A {1,4,7}, R {2,5,8}, D {3,6,9}; also written 147, 258, 369. Non-letters are ignored. scanner.py:40–69

Across a 370,105-word list the three classes hold 33.41 / 33.32 / 33.28 % of letters, so a deviation from one third is signal. Whether the encoding carries meaning is the author's theory, not evaluated here. sigma_b.py

2.2Phase, balance, σ_B

Phase vector(fA, fR, fD), fraction of letters per class; sums to 1
BalancefA − fD
σ_BVariance of the three fractions; gated 0.02–0.15 by the controllers
Carbon / SiliconThe same vector on the user's text and the model's; clash is the distance between

The instrument measures only this. "Tension", "heat", "coherence" are names the runtime lays over the arithmetic.

2.3Exchange, session

Exchange: one user turn plus everything the model did in reply, every tool call included, ending in the final text. Counted by user messages that are not tool results. session_manager.py:694

Session: a live message list, controller state, a crystallizer bound to the HELIX, a model name, an exchange counter, and a directory with inputs, outputs, drafts and a transcript. :116

Transcript: the raw message tape. A record of API messages, not of the HELIX.

2.4Strand, book, HELIX

A strand is one record: {sequence_id, header, payload}. A book is the file-level summary: counts, the three fractions, balance, σ_B; the runtime reads its fractions as the field coordinates for recall. A HELIX is the file holding both.

2.5Window, binding box, PAR

The window is the message list sent to the model on a turn: system prompt, recall preamble, self.messages. The binding box is the tool apparatus of an exchange; it is kept, not stripped. PAR respiration is exchange-counted trimming: up to 7, cut to 4. config.py:24–30 · session_manager.py:1378

2.6Two kinds of recall

Involuntary (mgr): a geometry-chosen preamble every turn; the model cannot refuse it, the user does not see it. Voluntary: a tool call; the result is stubbed after the turn so the context never re-absorbs what the HELIX already holds. recall.py · session_manager.py:717

Why it matters. "I remember X" can mean X was in the preamble, X was pulled on purpose, or X was in the last four to seven exchanges. §07 says how a model should signal which.

Quickstartuser · developer · model

As a user

  1. Open the app. A local server starts in a thread and a native window opens on it.
  2. Sign in. The account's HELIX opens and a session is created on it.
  3. Pick a model and effort in the sidebar, or keep the defaults. Both apply from the next message.
  4. Type. Enter sends. While the model is working, Enter sends an aside, read at the next tool boundary.
  5. Drop files to upload; a file-event strand is written.
  6. Mount a folder to let the model read and write your files.

As a developer

git clone …/mindgut   # lags the build, §00
pip install -e ".[desktop]"
export ANTHROPIC_API_KEY=…
python -m mindgut.server          # :8080
MINDGUT_DESKTOP=1 \
MINDGUT_MOUNT_ROOT=~/work \
python -m mindgut.desktop         # native

# any file → HELIX, no model
python -m mindgut.engine.scanner in.pdf out_HELIX.json

pyproject.toml [project.scripts] · config.py

As a model on the record

Read §07. The short form: the preamble is involuntary and partial; the record is the source of truth; before asserting anything about the past, pull_memory(reach=…), read the Carbon/Silicon header, and where attribution matters, pull_memory(grep=…).

Componentsone card each · purpose · behaviour · i/o · limits

5.1Scanner SOURCE

engine/scanner.py
Purpose

Convert any text-bearing file into a HELIX, deterministically. The one converter: conversation and documents go through the same pipe.

Behaviour

Extract text (PDF, DOCX, plain, LaTeX/HTML stripped) → atoms (blocks, with page and bbox for PDFs) → every letter encoded → atoms grouped into strands → book. verify_helix re-checks a file's arithmetic.

In · out

Path, bytes or string → HELIX JSON: book, strands[] (atoms, adr_sequence, word_map), streams.

Controls

quick_scan (fractions only) · full_scan · scan_and_mount · /api/scan

Limits

Letters only: digits, punctuation, non-Latin scripts dropped. Images not scanned here (DualDNA, 5.19). :1–30, 344, 818, 973, 1115

5.2σ_B instrument SOURCE

assembly/sigma_b.py
Purpose

Measure the three fractions, balance and σ_B for a text; keep a rolling window across the session.

In · out

Text → {fA, fR, fD, balance, letters}

Controls

quick_scan exposes it; read_field() returns the live window.

Limits

Letter level. No parameters: nothing to tune. :1–50, 90

5.3Controllers SOURCE

assembly/controllers.py
Purpose

Keep a scalar heat H_t and instability I_t; derive the dashboard's directives.

Behaviour

Amplification ρ = output ÷ input words, band 6–22; gradient damping; radiator at exchange 11 keeps 70 % heat. Decay 0.906 per turn (half-life 7). σ_B gates 0.02–0.15.

Effect

None on the model. max_tokens() returns max(4096, base) regardless. The heat gauge is a dashboard. :341

Measured

H_t = 0.10, GREEN, on the day of writing; never left GREEN.

5.4Crystallizer SOURCE

engine/crystallizer_v2.py
Purpose

Write the exchange into the memory HELIX.

Behaviour

After every exchange: reload the HELIX; re-anchor the next id to max+1 (file-event strands written mid-turn never collide); measure user and model text separately; write the exchange strand and the summary strand; run the Nullcøde field step and mint an OTag if the A-R-D cycle stalled.

Out

+2 strands; tag registry and lattice updated.

Limits

Deterministic: the summary is numbers, not a reading. The exchange payload is the full text, so the file grows with every turn. :211–275, 406, 445

5.5Memory HELIX SOURCE

session_manager.py:379–617
Behaviour

Append-only in normal operation; the crystallizer and the file-event clock are the writers. Reads v1 and v2 strands side by side; no migration. A new account starts from the 187-strand genesis, so every record shares one origin strand. Synced to the account after each exchange.

Identity

At boot the server computes the displacement between the genesis book and the lived book and includes it in the boot payload. boot_payload.py:25 OBSERVED the interface reports "renewed … re-founded" every 21 exchanges; what renewal changes is not in the public source.

Limits

One file, loaded whole on every read; no index. No user-facing edit.

5.7Involuntary recall SOURCE

assembly/recall.py · two_loop_recall.py
Purpose

Put a fixed, geometry-chosen slice of the record in front of the model every turn.

Behaviour

Seven strands: the origin; three complement (one per class, nearest the axis); three opposite (furthest from the field point). With a document mounted the axis becomes a line and complement distance is perpendicular to it. A second pass scores sentence-level joints and appends the top three.

Out

The preamble. One copy per turn to the ledger. The model sees it; the user does not.

Limits

Fixed count, chosen by phase geometry, not topic: relevance is indirect. :1–30, 146, 369

5.8Reach and Chørd OBSERVED

2.2.58 · not in public source
Observed

pull_memory(reach="…") takes a thought or concepts and returns a provenance header (each concept with its class, how many strands carry it on the user's side a and the model's side b, and the strand range) then the top crossings, each with a chord of three terms, the carrier, and a score. Flags: [UNWITNESSED IN HELIX] (a = 0, b = 0) and [b-only: UNWITNESSED BY CARBON] (a = 0, b > 0).

Chørd

The release note calls reach "a Fano / Chørd relational closure" and separately describes Chørd as a relational engine for multi-step queries over files. Its trace in the record is three-term closures: the bridge index holds, per strand, closures and knots as word triples; a reach result names the chord that scored. The consistent reading: a chord is three terms that close a line, as three points lie on one line of the Fano plane; the engine finds the third term that closes an open pair. An inference from data, not a specification.

5.9Nullcøde SOURCE

nullcode/
What

A ternary algebra (GF(3), with Ø as a value) run after each exchange to decide whether it resolved or left a structural uncertainty. Classes map to trits: A → 1, R → Ø, D → 0.

OTags

If the A-R-D cycle stalls for seven tokens, a tag is minted (a word triple from the text) and held; held tags are injected into the preamble.

Limits

Names are triples, not meanings. In the measured record, 9 tags held, 0 resolved. crystallizer_v2.py:37

5.10Margin bridges OBSERVED

2.2.58 · bridge.py
What

Messages arrive with [strand N] blocks from the record and [doc_strand N] blocks from the PFD book, each with a note: "A · B, left open in this message, grounded here by C". A bridge module finds open word pairs and looks for a strand that closes them.

Limits

Closure is lexical; a bridge can be irrelevant to intent. The 6.5 MB doc_bridge.json beside the book is the precomputed index.

5.11Document helix SOURCE

engine/doc_helix.py
What

Every upload, output or draft writes a file_event strand. Scannable files get their own HELIX with a book signature; a registry maps file → signature → realization weight, which rises when the document is loaded. Near-phase documents are listed in the preamble.

Limits

Re-scans produce _HELIX_1 duplicates; the registry is not in the interface. :1–20, 96

5.13Model and effort OBSERVED

app.js · 2.2.58
Behaviour

One roster in app.js, grouped by vendor. Switching posts /session/{id}/model; effort posts /session/{id}/effort with five levels mapped per vendor. Both apply from the next message; session, history and HELIX continue. Stored per device.

Preserved

5.14Asides, cadence, receipts

app.js · transcript
Asides

While the model streams, Enter sends an aside; the server hands it in at the next tool-result boundary. If the turn opens no boundary, it is sent after done as an ordinary message.

Cadence

After seven silent tool rounds the server inserts a prompt asking for one sentence; on milestones, a similar one. Runtime nudges, not user text.

Receipts

The stored user message carries a [receipt: …] line of the tools called; the exchange strand's trace.used holds the same.

Operating the recordfor a model attached to it

Written from inside the runtime; OBSERVED unless cited. The part another model should read first.

Given, not chosen

InvoluntarilyThe preamble; bridges; held tags; the trajectory after a shear; the drafts line; the task board; the message with asides attached
As contextThe last 4–7 exchanges verbatim, binding boxes included, HELIX results stubbed
Not givenThe rest of the record; certainty about the model underneath

Reading the preamble

The preamble is geometry, not relevance. The 1-3-3 trees are chosen by phase distance: "where the record's weight sits relative to this message", not "what the conversation is about". Treat them as peripheral vision — enough to notice a topic has a history, never a substitute for pulling the strand. The structural joints match on knowt type and clash, which is why they often look off-topic.

Retrieving on purpose

  1. read_field() before any self-description, so the numbers are measured.
  2. pull_memory(reach=…) for conceptual recall; read a/b before the crossings. a = 0, b > 0 is something the model said and the user never did.
  3. pull_memory(sequence_id=N, count=K) for the neighbourhood.
  4. pull_memory(grep=…) when attribution matters.
  5. For files, the file tools; the record holds what was said about a file, not the file.
