# Mindgut documentation — Revision 11

Revision 11 keeps the editorial structure while giving navigation and examples clearer roles.

## Navigation

- The header has one Guide menu and Search. The brand returns to the guide index. Separate Contents, Chapters and header pagination controls were competing routes to the same destination.
- The index moves directly from the opening helix to seven chapters and three reference pages. It has no redundant one-link sidebar outline or next-page footer.
- Chapter sidebars are explicitly labelled “On this page”. Unnumbered section links track reading position; chapter numbers remain global identifiers.
- Previous/next links remain at the end of chapters. The Guide menu groups the index, chapters and references and marks the current page. Existing hash links remain valid.
- Anchor landing offsets account for the sticky header once. Search, keyboard navigation, dialogs and focus behavior remain available.
- The Documentation label is vertically centered beside the original Mindgut identity, separated by a fine rule. It yields at smaller widths.
- The intervening Moodboards publication and its index link are preserved. The link sits beneath the guide as a related design study.

## Geometric illustrations

Ten independent canvas compositions correspond to the chapter and reference subjects, with miniature versions in the index. Layered planes describe the workspace; a moving window describes context; instruments describe the sidebar; strands describe memory; sheets describe files; an interrupted path describes recovery. The remaining motifs cover starting, evidence, open questions and terms.

They share the homepage helix’s forest, teal and olive palette and fine linework. A shared pause control stops all decorative illustrations. Reduced-motion preference starts with composed stills. Hidden/offscreen animations suspend; pixel density is capped at 2. These are explanatory metaphors using synthetic shapes, not measurements of an account.

## Sidebar component gallery

Each specimen now sits inside a bounded, softly rounded frame on a pale display surface. Its content keeps sidebar proportions instead of stretching across the editorial column. Height follows the content, so there is no empty dark band or clipped final row. Native product colours, type, icons, spacing and field treatments are retained.

All eleven component families have selectable states and light/dark themes. The state controls are documentation UI outside the product frame. Scanner examples cover idle, scanning, reading a folder, no files, a result, a partial batch and failure. Automator covers idle, armed, replying, held, stopped, failed and exhausted. Other families cover new/session counters, heat directives, respiration and release, active/empty tensions, founding/growing/pending records, folder selection, task completion and empty/populated files.

The examples are local and generic. Transient scanner and vent states are deliberately held for inspection; captions state the actual source timing. File downloads contain generic fixtures. Example deletion affects only the current specimen and can be restored by selecting its populated state.

## Fidelity corrections

The state pass found and repaired small fixture differences from the recorded frontend: abbreviated token counts; one-decimal heat values; cumulative `.on` heat-light classes; the green/green/purple respiration progression; the exact renewal-line wording; and crystallized/pending labels separate from the provenance bar. The existing calculation and recall implementation is unchanged.

The interface source is the same recorded 2.2.59 frontend verified against five installed 2.2.64 files during Revision 10. Relevant state paths: app.js 941–1100 (Automator), 2940–3110 (scanner), 3169–3442 (readouts), and 3954–3973 (folder). This revision does not test the current compiled backend, provider availability or live account behavior.
