Six backend questions

  1. Renewal

    What state is replaced, reset or retained when the 21-exchange renewal fires in the current backend?

    The installed frontend consumes renewal status, but does not implement the state transition.

  2. Heat

    Which current backend paths consume Hₜ or heat-level directives?

    The source output ceiling is fixed; the installed display alone cannot establish all current uses.

  3. Scanner and recall

    Does a completed sidebar scan automatically mount, index or enroll the result?

    Frontend status and an output file do not prove automatic recall enrollment.

  4. File and folder lifecycle

    What does DELETE remove from the account archive, and which folder handles survive a frontend clear or session end?

    The frontend requests deletion and clears local state. Server and native lifecycle guarantees are unverified.

  5. Token accounting

    What resets totals, and how does each provider map cache and thinking into the displayed fields?

    The displayed categories can overlap. Their sum is not a billing model.

  6. Tension tags

    How is a held tag resolved and where can a user inspect its lifecycle?

    The count is visible; a human interpretation of each tag is not supplied.

Other verification gaps

  • Cross-model continuity. Compare the same task and retrieved passages before and after a switch, retaining transcripts and outputs.
  • Current tool schemas. Confirm worker, terminal, memory and execution limits from the current runtime rather than carrying V05 values forward.
  • Sync and retention. Establish which local and archive copies survive failure, deletion, logout and an update.
  • Viewer behaviour. The local views loaded and selected modes were checked. Playback, sound and the interpretation of the displayed measures still need separate evaluation.
  • Measurement claims. Any claim that phase or σB detects authenticity, meaning or deception needs independent validation. Arithmetic implementation is not that validation.
