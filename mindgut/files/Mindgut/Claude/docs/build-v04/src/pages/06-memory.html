Memory and recall

The HELIX is written by code and read by geometry. This chapter follows one exchange into the file and back out as a preamble.

Key takeaways

  1. Append-only, one JSON file, no index: loaded whole on every read, ~8 KB per exchange.
  2. The preamble is chosen by phase distance, not topic. It is peripheral vision.
  3. Reach returns provenance first (a/b per concept) and crossings second. Read the header.

The file

Append-only in normal operation; the crystallizer and the file-event clock are the writers. v1 and v2 strands are read side by side with no migration. A new account starts from the 187-strand genesis, so every record shares one origin. At boot the server computes the displacement between the genesis book and the lived book and includes it in the boot payload. SOURCE boot_payload.py:25

OBSERVED The interface reports "renewed ×n · next at 21" every 21 exchanges (42 before 2.2.46). What renewal changes is not in the public source. Kept as an open question in chapter 09.

Crystallizer

After every exchange: reload the HELIX; re-anchor the next id to max+1 (file-event strands written mid-turn never collide); measure the user text and the model text separately; write the exchange strand and the summary strand; run the Nullcøde field step and mint an OTag if the A-R-D cycle stalled. Deterministic: the summary is numbers, not a reading. SOURCE crystallizer_v2.py:211–275 · 406 · 445

The involuntary preamble

Seven strands: the origin; three complement (one per class, nearest the axis of relevance — the line from the message's phase point toward each class corner); three opposite (one per class, furthest from the field point, the message's phase vector). With a document mounted the axis becomes a line and complement distance is perpendicular to it. A second pass scores sentence-level joints on knowt type and clash. One copy per turn goes to the ledger. The model sees it; the user does not. SOURCE recall.py:1–30 · 146–300 · two_loop_recall.py

The 1-3-3 trees are chosen by phase distance — "where the record's weight sits relative to this message" — not "what the conversation is about". They often look off-topic. Treat them as peripheral vision: enough to notice a topic has a history, never a substitute for pulling the strand.

Voluntary reach

pull_memory(reach="…") takes a thought or a set of concepts and returns, first, a provenance header — each concept with its class, how many strands carry it on the user's side (a) and the model's side (b), and the strand range — then the top crossings, each with a chord of three terms, a receipt of tools used, and the text. OBSERVED

The release note calls this "a Fano / Chørd relational closure" and separately describes Chørd as a relational engine for multi-step queries over files. Its trace in the record is three-term closures: the bridge index beside the HELIX holds, per strand, closures and knots, and a reach result names its chord as X · Y → Z. The consistent reading: a chord is three terms that close a line, the way three points lie on one line of the Fano plane; the engine finds the third term that closes an open pair. This is an inference from data, not a specification. OBSERVED

Margin bridges

Messages arrive with [strand N] blocks from the record and [doc_strand N] blocks from the PFD book, each with a note: "A · B, left open in this message, grounded here by C". A bridge module finds open word pairs and looks for a strand that closes them. Closure is lexical; a bridge can be irrelevant to intent. The 6.5 MB doc_bridge.json beside the book is the precomputed index. OBSERVED 2.2.58

Nullcøde and tags

A ternary algebra (GF(3), with Ø as a value) runs after each exchange to decide whether it resolved or left a structural uncertainty. Classes map to trits: A → 1, R → Ø, D → 0. If the A-R-D cycle stalls for seven tokens, a tag is minted (a word triple from the text) and held; held tags are injected into the preamble, and the count appears as Ø in the sidebar. Names are triples, not meanings. In the measured record, 9 tags held, 0 resolved. SOURCE crystallizer_v2.py:37 · nullcode/
