Your first session

  1. Open Mindgut and sign in.

    The desktop app starts a local server and opens its window. Wait for the record to load before sending work.

  2. Choose model and effort.

    The two menus are at the top of the sidebar. A changed choice applies to the next message; it does not revise a reply already in progress.

  3. Send a concrete request.

    Say what you want made or checked, which files matter, and what a successful result should include. When idle, Enter sends; Shift + Enter adds a line. During a turn, Enter submits an aside request. Its ASIDE, HEARD or QUEUED label distinguishes what happened.

  4. Inspect what comes back.

    Open the output and check the result. A reply or a checked task is not proof that the file is correct.

Model and effort

The installed menu has four vendor groups and five effort labels: Low, Medium, High, Extra-high and Max. The frontend defaults are Fable 5.1 and Extra-high. Saved choices can override those defaults.

Model and effort are stored in this device’s browser storage and sent to the session. A frontend defaults-version change can clear older saved choices once. They are not proof of account-wide settings. Higher effort can increase time and usage; the same label need not map to identical work across vendors.

Find the result

Output lists created files; Drafts lists documents still in progress; Input lists uploaded files. File links open or download their targets according to the browser or desktop handler. Preserve important files outside the session before deleting them or troubleshooting sync.

Normal and advanced mode

The mode control in the top bar switches between normal and advanced. Advanced adds Tokens, Hₜ, Respiration, Ø and HELIX, plus message diagnostics. Normal keeps the working controls. Automator is a separate desktop feature and can appear in either mode.

The neighbouring controls switch theme and show or hide the sidebar. Mode and theme are saved on the device. The icons are small; their hover text identifies them.

For developers

The readable backend snapshot is older than the installed app. This guide is not a verified installation recipe: its package manifest, dependencies and launch commands have not been reproduced. Use the repository’s instructions for the exact revision you intend to run.

  1. Identify the implementation.

    Record the repository commit and app version. Check the version boundary before applying a source claim to the current app.

  2. Isolate a development run.

    Confirm configuration and data paths before launch. Use a separate checkout and disposable example data.

  3. Verify the path you changed.

    For a frontend change, test the control and request. For a backend change, check its saved output and failure path. A rendered control alone is not an end-to-end test.
