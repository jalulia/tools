Chapter / 01

What Mindgut does

Understand the two parts: a workspace for doing the work, and a record that can carry earlier material into later turns.

01The workspace02The record03From message to record04What the record proves
Revision 08 · 23 October 2026Interface: 2.2.59Source and version scope ↗

The workspace

Mindgut brings a conversation with Mir, file work and a persistent record into the same workspace.

The chat is the working surface. The sidebar holds model and effort controls, tasks, files and optional instrument readouts. The installed interface lists fourteen models in four vendor groups: Claude, ChatGPT, Gemini and Grok. That is the shipped menu, not a guarantee that every provider is available to your account.

The model is selectable; the account record is shared across those choices. Change model or effort for subsequent messages. Wait until the current turn finishes when continuity matters.

The record

HELIX is a JSON record containing strands: text, headers and measurements. In the public source, a completed exchange writes an exchange strand and a numerical summary strand. File events can add other strands. A strand count is therefore not a count of conversations or turns.

The model receives selected material from that record alongside recent conversation. Storing text makes it available for later retrieval; it does not guarantee that a later reply will retrieve it, interpret it correctly or quote it faithfully.

From message to record

What the record does—and does not prove

PropertyWhat it means
Short working contextThe source retains a bounded list of recent exchanges. Scrolling the transcript does not resend all of it to the model.
Persistent retrievalEarlier text can return through recall. Persistence and successful retrieval are separate checks.
Measurements from codePhase and balance are arithmetic encodings of text. They are not evidence of truth, understanding, agreement or task completion.
No weight update in this pathThe inspected source changes context and stored data, rather than training the model’s weights.
Numerical summaryThe summary strand is computed JSON. The exchange strand can still contain a summary written by the model if that was part of its reply.

Your first session

  1. Open Mindgut and sign in.

    The desktop app starts a local server and opens its window. Wait for the record to load before sending work.

  2. Choose model and effort.

    The two menus are at the top of the sidebar. A changed choice applies to the next message; it does not revise a reply already in progress.

  3. Send a concrete request.

    Say what you want made or checked, which files matter, and what a successful result should include. Enter sends; Shift + Enter adds a line.

  4. Inspect what comes back.

    Open the output and check the result. A reply or a checked task is not proof that the file is correct.

Model and effort

The installed menu has four vendor groups and five effort labels: Low, Medium, High, Extra-high and Max. The frontend defaults are Fable 5.1 and Extra-high. Saved choices can override those defaults.

Model and effort are stored in this device’s browser storage and sent to the session. They are not proof of account-wide settings. Higher effort can increase time and usage; the same label need not map to identical work across vendors.

Bring files into reach

OperationUse it forWhat changes
UploadA file for this conversationDrop it into chat or use the composer’s + control. The file appears under Input.
Mount folderLocal files you want Mir to work onThe folder row gives the supported local tools a folder to operate within. Browser support and access can differ from desktop.
ScanA text-bearing document you want converted into a HELIXScanner creates a separate output record. The frontend does not demonstrate automatic enrollment into memory recall.

Uploading, mounting and scanning are different operations. Chapter 06 explains their boundaries.

Find the result

Output lists created files; Drafts lists documents still in progress; Input lists uploaded files. File links open or download their targets according to the browser or desktop handler. Preserve important files outside the session before deleting them or troubleshooting sync.

Normal and advanced mode

The mode control in the top bar switches between normal and advanced. Advanced adds Tokens, Hₜ, Respiration, Ø and HELIX, plus message diagnostics. Normal keeps the working controls. Automator is a separate desktop feature and can appear in either mode.

The neighbouring controls switch theme and show or hide the sidebar. Mode and theme are saved on the device. The icons are small; their hover text identifies them.

For developers

The readable repository snapshot is older than the installed app. The following commands describe that source snapshot; they have not been used to launch another app against your data in this review.

git clone https://github.com/The-Impossible-Outcomes-Co/mindgut
pip install -e ".[desktop]"
export ANTHROPIC_API_KEY=…
python -m mindgut.server
MINDGUT_DESKTOP=1 python -m mindgut.desktop
python -m mindgut.engine.scanner in.pdf out_HELIX.json

Run from an isolated checkout with its own data directory. See the version boundary before treating the snapshot as current implementation.

What the model receives

Revision 08 · 23 October 2026Interface: 2.2.59Source and version scope ↗

The working window

The visible transcript, the context sent to the model and the persistent record are three different things.

In the public source, an exchange is counted by a non-tool user message. It includes the assistant’s tool activity and response. After the seventh completed exchange, post-processing removes the oldest three exchanges and retains four. The next completed exchange brings the retained count to five.

Released exchanges can be retrieved if they were successfully written and retained in HELIX. The demo does not imply that every failed or interrupted turn reaches the record. The 21-exchange renewal counter is a separate mechanism.

Automatic recall

Before a model call, the source assembles recall information. Its outer selector chooses the first strand as origin, then up to three complement and three opposite entries, one from each eligible class. A further pass can add sentence-level material. This is not the entire record.

Complement selection uses the segment from the record’s field coordinates to the current message’s word-phase coordinates; a mounted document can add another segment. Opposite selection uses distance from the record’s field coordinates. The working demonstration shows that distinction.

V05 reported additional word-matched bridges in 2.2.58. That report is retained as historical evidence, rather than presented as a newly reproduced backend test. Retrieved material can be irrelevant; it is context to inspect, not an instruction to obey.

Deliberate recall

Mir can request earlier material with memory tools. The public source includes positional memory reads; V05 also reported concept reach and phrase search in its runtime. Their current server-side implementation and schemas have not been independently exercised here.

When a claim depends on earlier conversation, ask for the retrieved text and its strand identifier. A matching phrase proves occurrence in the retrieved material. It does not prove who endorsed it: people paste, quote, question and reject text. A search that finds nothing does not prove something was never said.

The public source shortens memory-tool results after the turn. Ask Mir to retrieve them again when exact wording matters.

Assess “I remember”

Possible basisWhat to check
Recent contextAsk which message it came from. Presence in context does not make the model’s interpretation correct.
Retrieved recordAsk for the strand identifier and exact passage. Read the passage in context.
Automatic selectionAsk whether the answer relied on recalled material, and request deliberate verification.
Inference or errorIf no source can be produced, treat the claim as unverified. Models can mistake an inference for a memory.

Know what changes state

Model and effort apply to subsequent messages. Folder selects local access. Scanner requests conversion. To Do changes task state. File links access artifacts; their × controls request deletion.

Automator is desktop-only. Set 1–25 automatic replies; the default count is 7. When armed, it waits for a final reply ending with “Beep boop.” and sends “Boop beep.”. Matching ignores case and trailing whitespace or certain formatting characters. It does not recognize general expressions of permission.

Your queued messages take priority. The frontend stops or parks the loop according to turn state; it disarms on a failed turn, exhausted count, missing trigger or new session. The active button and the composer’s Stop control can stop automation. Arming can immediately continue a qualifying previous final reply. Each automatic reply is a model turn with its usual usage.

Task checkboxes and deletion requests are different actions. A task marked complete only records its state; verify the artifact separately. The folder × and file × also have different behaviour; see their lifecycle boundaries.

Chapter / 05

Memory

Understand the record’s structure and the arithmetic that selects from it, without assigning those measurements more meaning than they support.

01The record02Two resolutions03A strand’s structure04Recall geometry05Tension tags06Viewer links
Revision 08 · 23 October 2026Interface: 2.2.59Source and version scope ↗

A record made of strands

HELIX is a structured JSON record. On successful crystallization, the source appends an exchange strand and a numerical summary after a completed exchange.

The installed founding file contains 187 strands. Later exchanges and file events add to the account record. Normal crystallization appends strands and updates book-level aggregates; it is not an immutable audit log, and “nothing is rewritten” would overstate what the file format guarantees.

The source loads the file whole. Size depends on text and metadata; V05’s roughly 8 KB per exchange came from one reported sample and is not a fixed storage budget. Local paths, sync and archive retention in the current compiled backend require separate verification.

Two measurement resolutions

For A–Z, number the letter from 1 to 26, then reduce its position to a single digit. Roots 1, 4 and 7 map to A; 2, 5 and 8 to R; 3, 6 and 9 to D. “N” is 14 → 5 → R.

Letter phase is the proportion of accepted letters in those three classes. Word phase first sums a word’s letter roots and reduces that sum, then counts one class per extracted A–Z word. These are different measurements. The public source retains both; its recall selector uses the word-level fields f147, f258, f369.

Balance is A share minus D share. In the source’s streaming instrument, σB is the population standard deviation of clause balances over up to seven nonempty clauses. With fewer than two clauses, the implementation returns zero; that is not evidence of perfect coherence.

Character counts and word extraction have separate A–Z rules. Numbers and most other scripts do not contribute. These encodings do not establish meaning, truth, authenticity or psychological state.

Illustrative values and an abbreviated header. This is a structural explanation, not a screenshot or a captured user exchange.

Recall, with the source geometry

For complement selection, the public source scores eligible speech strands against the segment from the record’s field point to the message point, one bucket per stored class. For opposite selection, it scores distance from the record’s field point. A small position term breaks geometric ties and slightly changes the score: it favours later strands for complement and earlier strands for opposite. The origin is the first strand.

At most one candidate per class is selected for each group; an empty bucket yields fewer. Seven selection entries need not mean seven distinct strands. An absent or nearly coincident message point triggers the source’s radial fallback. A mounted document adds another axis; that path is outside this demonstration.

Tension tags

The source feeds word classes to a ternary state machine. A stalled cycle can mint a tag from words in the text; held tags are carried as structural state. The Ø panel shows a count. It does not show the tags or explain which human question, if any, they concern.

The viewers

The HELIX panel links to /my-wave (“the helix as a standing wave”) and /my-helix (“View HELIX in 3D”). They open separate views. Both views loaded the current account through the local desktop server during this review. In the 3D viewer, Drift changed the geometry and Reset returned the view. In the wave viewer, Journey and Superpose produced visibly different arrangements. Playback and sound were not evaluated.

Inspect the actual wave viewer: Journey and Superpose

Upload, mount and scan

OperationEstablished by the operationSeparate check
UploadA file is accepted into the session’s Input list.Whether Mir has read it, extracted the right content or used it in the reply.
Mount folderThe supported local access path is associated with a folder.Which tools are available, how access is enforced, and whether a particular file was opened.
ScanThe frontend requests conversion and reports status; a resulting HELIX can appear under Output.Whether conversion completed correctly and whether the record was mounted or included in recall.

Scanner’s + accepts one or more files. Its folder button appears when a mount is active. Status is transient: the installed loadScanList() is empty, so the panel is not a persistent scan history. The source scanner handles text-bearing formats; image-only files may require extraction or OCR elsewhere.

The × controls

LocationFrontend actionBoundary
Output / Drafts / InputAsks “Delete [filename]?” and sends a DELETE request after confirmation.The readable frontend does not establish archive retention or recovery. Save a needed copy first.
FolderClears local UI references, the desktop mount-active flag and the folder display.The function does not itself call a backend unmount route. Full native or server handle revocation is unverified.
To DoRequests deletion of the selected goal or task.This changes the plan’s state; it does not establish what happened to associated files.

Do not treat ending a session as a verified guarantee that every folder handle has been revoked. That was an unsupported assurance in V05.

Drafts and outputs

The source’s document workflow opens a draft, appends content and finalizes it. Drafts persist in files as work progresses; finalization can convert Markdown into PDF or DOCX. Files created through other tool paths need not use that workflow.

A saved draft can preserve earlier chunks when generation is interrupted, but it is not immune to disk, sync or deletion failures. Check what is actually present before resuming. Finalization is a file-state transition, not a quality review.

Tasks

The To Do panel renders goals and steps, with checkboxes and deletion controls. The installed frontend sends changes to the session’s task routes. A checked box means marked done. It does not certify that a file exists, that dependencies were satisfied in practice or that a reviewer checked the result.

Tool families and their boundaries

FamilyPurposeEvidence boundary
MemoryRead earlier strands and retrieve stored material.Positional reads are in public source; newer reach and provenance behaviour were reported by V05.
Session filesRead inputs, write drafts, finalize outputs and access archives.Public-source workflows plus installed file-panel routes.
WorkspaceRun code and maintain files in a server workspace.Public source; current persistent-terminal behaviour is not independently reproduced.
Local filesOperate on files through the mounted-folder bridge.Installed frontend and bridge paths. Desktop and browser implementations differ.
WebFetch, search or use an available browser tool.Tool availability depends on the running backend and environment.
ImagesGenerate or edit images through an available image tool.Do not infer visual accuracy from successful generation; inspect the resulting pixels.
WorkersDelegate a separate job to a background process.Worker schemas and completion handling described in V05 have not been revalidated against this compiled backend.

The public source sets a 15-round tool loop and a 300-second wall-clock guard, checked between rounds. If either guard is reached, its final synthesis call has a 45-second timeout. Provider requests, image generation, desktop bridges and worker tasks can have different waits. These values are not an end-to-end response-time promise.

Background workers

V05 reported up to nine workers, separate workspaces, selectable models and a scanned completion report. Those are inherited runtime observations, not limits confirmed by this review. Ask the active runtime for its tool schema and inspect the produced report before relying on a particular limit or workflow.

Automator is distinct: it sends continuation messages into the main conversation. A background worker runs a separate job.

When something fails

Preserve visible work first. Then identify which part failed and verify what was already written.

01Three places to check02A turn fails03Provider errors04Model-switch stalls05Other cases
Revision 08 · 23 October 2026Interface: 2.2.59Source and version scope ↗

Three places to check

PlaceWhat it can showWhat it does not prove
Visible transcriptText already streamed to the screen.That the text reached the working window or persistent record.
Working contextMaterial sent to the next model call.That the entire visible transcript is included.
HELIX and filesSuccessfully stored strands and artifacts.That a failed turn was stored, or that all local data has synced.

A turn fails or stops

  1. Preserve what you can see.

    Copy needed text and save available files before refreshing, retrying or restarting.

  2. Read the actual error.

    Identify whether it came from the provider, connection, tool or app. A later error does not explain an earlier failure by itself.

  3. Check for completed side effects.

    An output or file edit may already exist even if the turn failed. Inspect it before repeating a request that writes or deletes.

  4. Restate the missing request.

    Include any needed text from the failed turn. Ask Mir to verify existing outputs and retrieve the relevant strands before continuing.

V05 described an incident where streamed questions could not be recovered from the record. That is a useful failure example, not proof that every failure has the same persistence behaviour.

Provider errors

Read the error message before choosing a remedy. Credit and rate-limit failures are possibilities; network errors, authentication, unavailable models, invalid requests and service failures are others. A retry may need time, a corrected configuration or another available model.

A provider failure does not establish that no record or artifact was written earlier in the turn. Verify what exists before resending.

A model switch appears stalled

Wait for the active turn to settle or use Stop before changing models. The frontend says changes apply from the next message. If a switch appears stalled, preserve visible work, inspect the status, then send a new message that states what should continue and which files already exist.

The shared record is the intended continuity path. This review did not run a model-switch experiment or verify that every vendor resumes a mid-tool turn equivalently.

Other cases

SymptomUseful next check
Loading does not finishPreserve work. Inspect connectivity and app status; record loading can contribute, but a large HELIX is not the only possible cause.
Mir cannot see an earlier imageAsk for the original file to be read again. In the public source, earlier image payloads are scrubbed from context to reduce its size.
A recalled passage is irrelevantAsk Mir to identify its source and verify the intended context instead of adopting it as an instruction.
Task state or files differ between devicesCheck the local result and account archive separately. A visible local update is not proof of completed sync.
A browser tool fails to launchUse an available text fetch or another supported tool, and state what could not be checked visually.
Work seems missing after an updateCheck saved outputs, drafts and the account archive. Avoid assuming that a reinstall or restart will restore unsynced work.

Reference / R2

Open questions

Uncertainty belongs beside the claim it limits. These questions need backend evidence or controlled experiments.

01Six backend questions02Other verification gaps
Revision 08 · 23 October 2026Interface: 2.2.59Source and version scope ↗

Six backend questions

  1. Renewal

    What state is replaced, reset or retained when the 21-exchange renewal fires in the current backend?

    The installed frontend consumes renewal status, but does not implement the state transition.

  2. Heat

    Which current backend paths consume Hₜ or heat-level directives?

    The source output ceiling is fixed; the installed display alone cannot establish all current uses.

  3. Scanner and recall

    Does a completed sidebar scan automatically mount, index or enroll the result?

    Frontend status and an output file do not prove automatic recall enrollment.

  4. File and folder lifecycle

    What does DELETE remove from the account archive, and which folder handles survive a frontend clear or session end?

    The frontend requests deletion and clears local state. Server and native lifecycle guarantees are unverified.

  5. Token accounting

    What resets totals, and how does each provider map cache and thinking into the displayed fields?

    The displayed categories can overlap. Their sum is not a billing model.

  6. Tension tags

    How is a held tag resolved and where can a user inspect its lifecycle?

    The count is visible; a human interpretation of each tag is not supplied.

Other verification gaps

  • Cross-model continuity. Compare the same task and retrieved passages before and after a switch, retaining transcripts and outputs.
  • Current tool schemas. Confirm worker, terminal, memory and execution limits from the current runtime rather than carrying V05 values forward.
  • Sync and retention. Establish which local and archive copies survive failure, deletion, logout and an update.
  • Viewer behaviour. The local views loaded and selected modes were checked. Playback, sound and the interpretation of the displayed measures still need separate evaluation.
  • Measurement claims. Any claim that phase or σB detects authenticity, meaning or deception needs independent validation. Arithmetic implementation is not that validation.
