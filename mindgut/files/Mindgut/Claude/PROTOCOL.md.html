# PROTOCOL.md — how work moves through `Mindgut/Claude/`

V01 · 2026-10-19. Read this and `NOW.md` before touching anything. Write `UPDATE_LOG.md` before you finish. Craft standards live in `fidelity.md`; this file is only about files, versions and records.

## 1 · Authority

- `Mindgut/Claude/` is the Claude working area for the Mindgut project. Everything in it is created, versioned and logged by these rules.
- The rest of `Mindgut/` (`inputs/`, `outputs/`, `sandbox/`, `helixes/`, `drafts/`, client folders) is **read-only** from here. They are the harness's own stores and other lineages. Reference them by path; never edit, move, rename or build inside them.
- **Never delete. Never overwrite.** Superseded work moves to `_archive/`; doubtful files move to `_quarantine/` with a manifest. Julia does the final pass herself.
- Never run a builder or renderer that writes to hardcoded absolute paths outside this folder.

## 2 · The session loop

1. Read `NOW.md` (what is current) and the top of `UPDATE_LOG.md` (what changed last).
2. Do the work in the right folder (§3). New output = new version number (§4).
3. Render and review before calling anything done (`fidelity.md` §0.4, §1; `tools/render.js`).
4. Run `python3 tools/verify.py`. Fix drift it reports.
5. Log the change in `UPDATE_LOG.md` (§6.1) and update `NOW.md` if what is current changed.
6. Deliver early and incrementally: the first usable draft is saved before refinement starts.

## 3 · Folders

| Folder | Holds | Naming |
|---|---|---|
| `brief/` | the creative brief and addenda | `Mindgut_Brief_V01.md`; addenda `Addendum_YYYY-MM-DD_slug.md` |
| `references/` | the reference canon: one entry per reference with editorial status; images routed by path, copied only if the source is volatile | `REFERENCE-CANON.md` (index) + `R-NN-slug.md` entries |
| `studies/` | high-fidelity studies, one folder each | `ST-NN-slug/` containing `STUDY.md` + `ST-NN-slug_V01.html` … |
| `work/` | resolved pieces that carry the language: hero, conversation, HELIX interaction, site, social, advertising | `W-slug/` containing `W-slug_V01.html` … |
| `presentation/` | the deck / visual sequence | `Mindgut_Presentation_V01.html` … |
| `decisions/` | numbered decision records | `D-NNN-slug.md` |
| `reviews/` | render-and-critique passes | `YYYY-MM-DD-slug/` with `shots/`, `FAULTS.md` |
| `tools/` | verify, snapshot, log, render scripts | — |
| `_archive/` | dated snapshots of superseded versions | `YYYY-MM-DD-slug/` + `INVENTORY.md` |
| `_quarantine/` | files of doubtful status, awaiting Julia | `YYYY-MM-DD/` + `MANIFEST.md` |

Names: ASCII, no spaces, ISO dates, zero-padded numbers. `_LeadingUnderscore/` means not-current (archive, quarantine, templates).

## 4 · Versioning

- **Masters carry honest version numbers:** `name_V01`, `name_V02` … A new version is a new file; the previous file stays where it is until it is archived. Never `final`, `final2`, `(1)`, `copy`.
- **Bump on any change that was delivered or reviewed.** Working edits inside one session on an unreviewed draft may stay in the same version number; once a version has been rendered into `reviews/` or logged, the next change is a new number.
- **Identity is content, not timestamps.** When two files might be the same, compare `sha256`, not dates (`tools/snapshot.py --inventory` prints hashes).
- **One current pointer:** `NOW.md` names the current version of every live thing. Nothing else is "the latest." No `latest.html` slot copies. If a stable filename is needed for a published surface, that surface is documented in `NOW.md` as a slot surface with the master version it currently holds.
- **Snapshots** (`_archive/YYYY-MM-DD-slug/`) are copies with an `INVENTORY.md` (path, size, sha256) and, when a milestone, a `HANDOFF.md` and a contact sheet. `tools/snapshot.py` makes them; it never moves originals.
- **Demotion inside a work folder:** a rejected variant that must stay visible next to its siblings goes to `<folder>/_superseded/` with a one-line reason in `UPDATE_LOG.md`. This is the same convention used in Ø.
- **Provenance vocabulary** (same as the Ø Operating Spec, plus `known_failure`): `canonical` · `directional` · `historical` · `technical_reference` · `known_failure` · `excluded`. Use it on reference entries and in `NOW.md`. Do not invent a parallel one.
- **Git is optional.** This folder works without it. If Julia initializes a repo, do it from the Mac's own shell (the remote shell cannot delete `.git` lock files, so commits from it will wedge). Versioning rules above still apply inside the repo.

## 5 · Editing

- **Single-file HTML** per study or piece: markup, CSS, JS and fonts in one file. No fetch, no CDN.
- **Edit the source, not the output.** If a file is generated, keep the generator in `tools/` and note what version's fixes it contains at the top of the script.
- **Measured constants are named at the top of the file** (ramps, offsets, registration, scale units). Copy them; do not re-derive.
- **Edit the brief only by addendum.** `Mindgut_Brief_V01.md` is the source as received. Changes of direction become a dated addendum plus a decision record.
- **The harness stores are not edit surfaces.** A file from `outputs/` or `inputs/` that needs changing is copied into the right folder here under a new name with its origin written in the file header and in the log.

## 6 · Records

### 6.1 `UPDATE_LOG.md` — mandatory, newest first, same session
Every entry:
```
## 2026-10-19 · who · slug
- Produced: exact filenames and versions
- Changed: what and why (quote spec/copy changes verbatim)
- Landed: local path; if published, deploy/commit id and surface
- QA: the specific checks run (render sizes, console, verify.py result, hash compare)
- Open: anything left undecided
```
`python3 tools/log.py "slug" --who claude` prepends a filled template.

### 6.2 `NOW.md` — the status board
Three lists: **Current** (thing → version → path → status), **Mid-flight**, **Awaiting a decision**. Must be readable in ten seconds. `verify.py` checks that every path in it resolves.

### 6.3 `decisions/D-NNN-slug.md`
One decision per file: date, decision, reasoning, what it supersedes, status. Decisions are numbered so a later one can override an earlier one explicitly. Paired decisions (accepted + rejected + reason) are the preferred form. Nothing in the brief is settled until it has a decision record.

### 6.4 `reviews/YYYY-MM-DD-slug/`
`shots/` (desktop + ~390 renders, per-section PNGs, `console-errors.txt`) and `FAULTS.md`: fault list per element, what was patched, what remains. A review that did not render is not a review.

### 6.5 `references/`
`REFERENCE-CANON.md` indexes every entry with its status. Each `R-NN-slug.md` follows `_entry-template.yaml`. Statuses are never averaged.

### 6.6 `_quarantine/YYYY-MM-DD/MANIFEST.md`
Original path → quarantine path, size, sha256, reason, suggested disposition. Julia decides. Nothing in quarantine is deleted by Claude.

## 7 · Verification

- `python3 tools/verify.py` — read-only; exit 0 clean, 1 drift. Checks: required files, `NOW.md` paths resolve, version naming, forbidden names (`final`, `copy`, ` (1)`), spaces in new names, every study has `STUDY.md`, every archive/quarantine folder has its inventory/manifest, and whether anything newer than the last log entry is unlogged.
- `node tools/render.js <file.html> <outDir> [w h]` — Playwright screenshots (full page + per `<section>` + `[data-shot]`) and `console-errors.txt`. Run at 1440×900 and 390×844.
- `python3 tools/snapshot.py <folder> <slug>` — copies into `_archive/YYYY-MM-DD-slug/` with `INVENTORY.md`. `--inventory` alone prints hashes without copying.
- Publishing anywhere (WØRKHUB, Pages, a share): compare deployed bytes to the master by hash, re-check after the deploy settles, list every surface that carries the artifact, log the deploy id.

## 8 · Handoff

At every milestone: `_archive/YYYY-MM-DD-slug/HANDOFF.md` (what it is, where it is, how to run it, what is owed), the `UPDATE_LOG.md` entry, and an update to the project doc in the Ø Claude project (`claude/mindgut-claude-folder.md`) so the next session starts from the record, not from memory.
