A record that
outlasts the model.

Mindgut keeps a conversation as a measured file, puts a fixed slice of that file in front of a language model on every turn, and holds the model's own working context to seven exchanges. Continuity comes from the record, not the window.

00

Scope and evidencewhat was read · how claims are marked

This document specifies the Mindgut desktop application at build 2.2.58: its runtime, the memory file it keeps, the tools a model can call inside it, and the operating rules for a model attached to the record. It is written for a developer or designer who has not seen any conversation and should be able to work from it alone.

The public repository is two and a half months behind the shipped build and the build ships compiled Python. For anything added after August 2026 the readable evidence is the shipped frontend (app.js), the application log, and the data files the runtime writes. Those components are documented from that evidence and marked accordingly; nothing is described from memory of a conversation.

No personal information appears in this document. Example strands are drawn from a real record but shown as measurements only; where text is needed, it is synthetic and marked as such.

01

Overviewwhat the system is · what it is not

Mindgut is a desktop and web application that wraps a large language model in a persistent, measured record of the conversation. The record is a file the user holds, called a HELIX. Each turn is converted by deterministic code into two entries (strands) in that file; the conversion uses no model. On every turn a fixed selection of past strands is placed in front of the model without the model asking for it (involuntary recall), and the model can read the record on purpose through tools (voluntary recall). The model's working context is kept short by design: at most seven exchanges, trimmed back to four (PAR respiration).

The persona that speaks is Mir. The underlying model can be switched mid-session between four vendors' models from a roster in the sidebar; the session, the history and the HELIX continue across the switch. app.js "Mid-chat model switcher"

Underneath the product is one piece of arithmetic. Every letter of every message is mapped to one of three classes by its position in the alphabet. The three class fractions form a phase vector; their variance is σ_B; their difference is balance. These are what the runtime measures, stores on each strand, uses to choose what to recall, and uses to decide when to trim. The author's theory behind the arithmetic is called Paradox Field Dynamics (PFD); the 774-strand book that states it ships inside the application and is consulted by the runtime. The arithmetic is self-contained and is described here without the theory. engine/scanner.py:40–70

Not

A vector databaseRecall is geometric over three-component phase vectors and word co-occurrence, not embeddings. assembly/recall.py
A summariserThe "summary" strand is a numeric delta record, not model-written prose. crystallizer_v2.py:406
A long-context chatThe window is bounded at seven exchanges by design. config.py:29–30
A fine-tuned modelNothing in any model's weights changes. "Learning" means the record changes what the next turn is given.

Three layers, five components

The author's own map: five components (the PFD reference lattice, three controllers, the memory HELIX, involuntary recall, the σ_B instrument) and three layers on top (rolling shear, deterministic crystallizer, pressure gauge). This document follows the same decomposition and adds what 2.2.58 added. CONTEXT.md

02

Conceptsdefined once · used without re-definition

Z₃ encoding and the three cosets

Letter root. Each letter A–Z is numbered 1–26 and reduced to its digital root (repeated digit sum, 1–9). Non-letters are 0 and ignored. scanner.py:40–61

Coset. The root is placed in one of three classes: {1,4,7} → A (assertion), {2,5,8} → R (relation), {3,6,9} → D (derivation). Also written 147, 258, 369. scanner.py:63–69 The names are the author's labels; the computation does not depend on them.

Flatness. Across a 370,105-word English list the three cosets hold 33.41 %, 33.32 % and 33.28 % of letters. sigma_b.py docstring This is why a deviation from one third in a given text is treated as signal. Whether the encoding carries meaning is the author's theory and is not evaluated here.

Phase vector, balance, σ_B

Phase vector(fA, fR, fD): fraction of letters in each coset. Sums to 1. Older fields name it (f147, f258, f369). scanner.py measure_letter_stream
BalancefA − fD. Positive: assertion-heavy; negative: derivation-heavy. sigma_b.py measure()
σ_BVariance of the coset fractions. Read by the runtime as a coherence gauge; the controllers gate between 0.02 and 0.15. controllers.py:77–78
Carbon / SiliconThe same vector computed separately on the user's text (user_phase_vector) and the model's (assistant_phase_vector). Phase clash is the distance between them. exchange strand header

What the instrument measures is only this: letter-class fractions and their arithmetic. It does not measure sentiment, topic, truth or intent. "Tension", "heat" and "coherence" are names laid over the arithmetic by the runtime, and this document keeps the two apart.

Strand, book, HELIX

Strand. One record in a HELIX: {sequence_id, header, payload}. The header carries title, type, coset, checksum and, on newer strands, the phase vectors and measurements; the payload is text or null. scanner.py build_strand

Book. The file-level summary: source, strand and letter counts, the three fractions, balance, σ_B. The runtime reads the book's fractions as the field coordinates for recall. recall.py compute_field_coordinates

HELIX. The JSON file holding book and strands. Three kinds are in use:

  • Memory HELIX — the account record, grown by the crystallizer.
  • Genesis HELIX — the 187-strand seed every new account starts from; shipped as data/boot_HELIX.json. Every record therefore shares the same origin strand.
  • Document HELIX — a scan of any file into the same format: the 774-strand PFD book, and every outputs/*_HELIX.json.

Exchange, session, transcript

Exchange. One user turn plus everything the model did in reply — every tool call and result — ending in the final text. The runtime counts exchanges by counting user messages that are not tool results. One exchange with sixty tool calls is one exchange. session_manager.py:694–713

Session. One live Session: a message list, a controller state, a crystallizer bound to the memory HELIX, a model name, an exchange counter, and a directory with inputs/ outputs/ drafts/ and a transcript. session_manager.py:116–200

Transcript. The raw message tape, saved after every exchange: {session_id, created, updated, model, ephemeral, exchange_count, messages[]}. A record of API messages, not of the HELIX. save_transcript

Ephemeral

Console or test mode: the crystallizer writes to a scratch HELIX seeded from the genesis book that dies with the session. Registered accounts are never ephemeral. session_manager.py:118–123

Context window, binding box, PAR

Context window here means the message list sent to the model on a turn: the system prompt, the recall preamble, and self.messages. It is not the model's token limit.

Binding box. The tool-call apparatus of one exchange (assistant tool_use blocks and user tool_result blocks). It is persisted inside the exchange, not stripped. session_manager.py:1332–1365

PAR respiration — the author's name; plainly, exchange-counted trimming. The window holds up to SHEAR_INHALE = 7 exchanges. When the count reaches seven after an exchange, the oldest are cut so that SHEAR_EXHALE = 4 remain. config.py:24–30 · session_manager.py:1378–1398

Two kinds of recall

Involuntary recall (product name: mgr). Before every turn the runtime selects strands from the memory HELIX by geometry and places a preamble in front of the model. The model does not request it and cannot turn it off. The user does not see it. recall.py: "Not optional. Not narrated."

Voluntary recall. The model calls a tool: pull_memory (by reach, by position, by grep), pull_strand, mount_helix + pull_mounted, browse_archive. The result enters the context as a tool result; after the turn its payload is replaced by a stub so the context does not re-absorb what the HELIX already holds. session_manager.py:717–754

Why the distinction matters. "I remember X" can mean X was in the preamble this turn, X was pulled on purpose, or X was in the last four to seven exchanges. §07 sets out how a model attached to the record is expected to signal which.
03

Quickstartuser · developer · model

As a user

  1. Open the application. It starts a local server in a thread and opens a native window on it. CONTEXT.md "Desktop Mode"
  2. Sign in. The desktop app opens the account's HELIX and creates a session on it. app.js desktopLogin → _openDesktopHelix → createSession
  3. Pick a model and effort in the sidebar or keep the defaults (claude-fable-5-1, xhigh). Both apply from the next message. app.js MG_DEFAULT_MODEL, MG_DEFAULT_EFFORT
  4. Type. Enter sends. While the model is working, Enter sends an aside, read at the next tool boundary without starting a new turn. app.js "Asides"
  5. Drop files on the chat to upload; they land in the session's inputs/ and the account archive, and a file-event strand is written. routes/files.py · doc_helix.py
  6. Mount a local folder to let the model read and write your files.

As a model attached to the record

Read §07. The short form: the preamble is involuntary and partial; the record is the source of truth; before asserting anything about the past, pull_memory(reach=…), read the Carbon/Silicon header, and where attribution matters, pull_memory(grep=…).

05

Component referencepurpose · behaviour · i/o · dependencies · controls · limits

5.1 Scanner SOURCE

Purpose. Convert any text-bearing file into a HELIX, deterministically. Behaviour. Extract text (PDF via PyMuPDF, DOCX, plain text; LaTeX and HTML stripped); split into atoms (text blocks with page and bbox for PDFs); encode every letter; group atoms into strands; roll up to a book. verify_helix re-checks a file's arithmetic. Inputs. Path, bytes or string. Outputs. HELIX JSON with book, strands[] (each with atoms, adr_sequence, word_map), streams.

Controls. quick_scan(text) (fractions only), full_scan, scan_and_mount; the /api/scan routes. Limits. Letters only: digits, punctuation and non-Latin scripts are dropped. Images are not scanned here (§5.18). scanner.py:1–30, 344–360, 818, 973, 1115

5.2 σ_B instrument SOURCE

Purpose. Measure coset fractions, balance and σ_B for a text, and keep a rolling window across the session (SigmaBWindow). Inputs. Text. Outputs. {fA, fR, fD, balance, letters}. Controls. None directly; quick_scan exposes it; read_field() returns the live window reading. Limits. Letter level; no parameters, so nothing to tune. sigma_b.py:1–50, 90

5.3 Controllers SOURCE

Purpose. Maintain a scalar heat H_t and instability I_t from the σ_B reading and word counts, and derive operator directives for the interface. Behaviour. Three equations: α_ρ (amplification ρ = output words ÷ input words, target band 6–22), α_g (gradient damping), and a radiator discharge at exchange 11 retaining 70 % heat / 60 % instability. Passive decay every turn: H_t × 0.906 (half-life seven turns), I_t × 0.75. σ_B gates accumulation between 0.02 and 0.15.

Effect on the model: none. max_tokens() returns max(4096, base) regardless; "α_ρ is computed and logged but not coupled." The heat gauge is a dashboard. controllers.py:40–78, 161–240, 341–352

5.4 Crystallizer SOURCE

Purpose. Write the exchange into the memory HELIX. Behaviour. After every exchange: reload the HELIX; re-anchor the next sequence id to max+1 so file-event strands written mid-turn never collide; measure user and assistant text separately; write the exchange strand (title = first eight words of the user text; payload = both texts; header = combined and separate phase vectors, geometry, nullcode snapshot, tool trace) and the summary strand (balance drift, winning coset, per-sentence measurements, resonance). Then run the Nullcøde field step: if the A-R-D cycle stalled, mint an OTag and HOLD it. Outputs. +2 strands; tag registry and lattice updated. Limits. Deterministic: the summary is numbers, not a reading. The exchange payload is the full text, so the file grows with every turn. crystallizer_v2.py:211–275, 406, 445

5.5 Memory HELIX SOURCE MEASURED

Behaviour. Append-only in normal operation; the crystallizer and the file-event clock are the writers; reads go through a cached loader invalidated after each write. The runtime reads v1 and v2 strand formats side by side ("bilingual reader"); there is no migration. Seeding. A new account starts from the 187-strand genesis book, so every record shares one origin strand. Sync. On desktop the file is pushed to the account service after each exchange; .synced records the version. Controls. None for editing; two viewer pages read it; the admin console can inspect it. Limits. One file, loaded whole on every read; no index. session_manager.py:379–399, 486–617 · CONTEXT.md "v1 / v2 Coexistence"

Identity delta. At boot the server computes the displacement between the genesis book and the lived book and includes it in the boot payload; the author's framing is that the displacement is the identity. boot_payload.py:25–84 OBSERVED The interface reports "renewed at exchange N — re-founded through the PFD helix" every 21 exchanges (42 until 2.2.49); what renewal changes is not in the public source.

5.7 Involuntary recall — mgr SOURCE MEASURED

Purpose. Put a fixed, geometry-chosen slice of the record in front of the model every turn. Behaviour. select_four (the name is historical) returns seven strands: strand 1 (origin), three complement (one per coset, nearest the current axis), three opposite (one per coset, furthest from the field point). The axis is the current field coordinates; when a document HELIX is mounted the axis becomes a line from the memory field to the mounted field and complement distance is perpendicular distance to that line. A second pass (structural_recall) scores sentence-level joints among 13–21 candidates and appends the top three with knowt type, phase clash, balance and σ_B.

Output. The preamble; one copy per turn is appended to the ledger. The model sees it; the user does not. Controls. None. Limits. Fixed count; chosen by phase geometry, not topic, so relevance is indirect. recall.py:1–30, 146–172, 369 · session_manager.py:985–1005

5.8 Geometric reach and Chørd OBSERVED · 2.2.58

What is observed. pull_memory(reach="…") takes a thought or a set of concepts and returns: a provenance header listing each concept with its coset, how many strands carry it on the user's side (a, Carbon) and the model's side (b, Silicon), and the strand range; then the top crossings, each with a chord of three terms (X · Y → Z), the carrier (a∩b crossing-witnessed, or b Silicon-only), and a score. Two flags are defined: [UNWITNESSED IN HELIX] (a = 0, b = 0) and [b-only: UNWITNESSED BY CARBON] (a = 0, b > 0).

Chørd. The release note describes reach as "a Fano / Chørd relational closure across your HELIX", and separately describes Chørd as a relational data engine for multi-step queries over files. Inside the record its trace is three-term closures: the .bridge.json beside the HELIX holds, per strand, closures (a hash and a word triple) and knots (lists of word triples); a reach result names the chord that scored. The consistent reading is: a chord is three terms that close a line, as three points lie on one line of the Fano plane; the engine finds the third term that closes an open pair. This is an inference from data, not a specification. The engine's code is not in the public repository. release note (memory strand) · account_sync.json.bridge.json · reach output

5.9 Nullcøde and OTags SOURCE

Purpose. A ternary algebra (GF(3), with the void value Ø as a first-class element) that the crystallizer runs after each exchange to decide whether the exchange resolved or left a structural uncertainty. Behaviour. Cosets map to trits (A → 1 signal, R → 2 Ø, D → 0 ground). A triadic state machine tracks the A-R-D cycle through the text; if it stalls for seven tokens an OTag is minted (a named uncertainty whose name is a word triple from the text) and HOLD'd. Tags accumulate bonds across exchanges; resolution cascades. Held tags are injected into the preamble as HELD (Ø). Outputs. Tag registry, lattice, the nullcode block on each exchange strand. Controls. None; an explorer page exists. Limits. Tag names are word triples, not meanings; in the measured record none of nine tags has ever resolved. CONTEXT.md "Nullcøde" · crystallizer_v2.py:37–47 · tag_registry.json

5.10 Margin bridges OBSERVED · 2.2.58

User messages arrive with appended blocks of two forms: [strand N] with a bridge note ("A · B, left open in this message, was grounded here by C") and the strand's text; and [doc_strand N — PFD Ø 2.1.1: title] with the same note and the book's text. The release note describes the mechanism: a bridge module finds open word pairs in the user's message and looks for a strand, in the memory HELIX or in the PFD book, that closes them. The ledger line records bridge open=[…] named=… sent=N.

Limits. Closure is lexical, so a bridge can be irrelevant to intent; a model is expected to treat bridges as peripheral vision, not as instructions. The 6.5 MB PFD_HELIX.json.doc_bridge.json beside the book is the precomputed index for the document side.

5.11 Document helix and file events SOURCE

Purpose. Put files on the same timeline and in the same format as conversation. Behaviour. Every upload, output or draft writes a file_event strand to the memory HELIX. Scannable files also get their own document HELIX with a book signature; a registry maps file → signature → realization weight, which rises when the document is actually loaded. Documents whose signature is near the conversation's phase are listed in the preamble as DOCUMENTS. Limits. Re-scans produce _HELIX_1.json duplicates; the registry is not exposed in the interface. doc_helix.py:1–20, 96–146 · session_manager.py:1010–1045

5.13 Model and effort OBSERVED · 2.2.58 frontend

Behaviour. The sidebar roster is one list in app.js, grouped by vendor. Switching posts to /session/{id}/model and applies from the next message; the session, history and HELIX continue. Effort posts to /session/{id}/effort with five levels mapped per vendor (Anthropic output_config.effort, OpenAI and xAI reasoning.effort, Gemini thinking levels). Defaults as of 2.2.57: claude-fable-5-1, xhigh; a prior device pick is cleared once when the defaults version changes. Stored per device in localStorage. Limits. Per device, not per account. The public source has only one Anthropic model; how 2.2.58 reaches the other vendors is not readable. app.js MG_MODEL_GROUPS, MG_EFFORT_LEVELS, MG_DEFAULTS_FROM

What a switch preserves, in principle: the HELIX, the preamble mechanism, the last four to seven exchanges, the task board. What it cannot preserve: anything the previous model held only in its own weights or thinking. The claim that identity survives the switch rests entirely on the record being the source of continuity.

5.14 Asides, cadence, receipts

Asides. While the model is streaming, Enter sends the text to the server as an aside; the server hands it in at the next tool-result boundary, so the model reads it the next time it looks up from a tool. If the turn opens no boundary, the aside is returned after done and sent as an ordinary message. In the transcript an aside appears as a user message with an "aside while you were working — not a new turn" prefix. app.js "Asides" · transcript

Cadence. After seven silent tool rounds the server inserts a prompt asking the model to surface one sentence; on task milestones, a similar prompt. These are runtime nudges, not user text. MEASURED

Receipts. The user message as stored in the HELIX carries a [receipt: tool(args), …] line listing the tools called; the exchange strand's trace.used holds the same. This is how a reader checks which files the model actually looked at. MEASURED

5.15 Background agents OBSERVED · 2.2.58

agent_spawn(task, name, model, effort, max_rounds ≤ 30) starts a worker that runs across turns in its own sandbox directory; up to nine at once. Its final report is scanned into a standalone HELIX in outputs and read by strand with agent_read; nothing a worker generates touches the memory HELIX. A dock tracks unread workers. Limits. Workers share nothing with the main session except files.

5.16 Sync, sign-in, updater OBSERVED · 2.2.x

  • Desktop sign-in opens the account's HELIX and creates a session on it; only a 401 from the account signs a person out; an unreachable account continues on the stored sign-in (2.2.42). app.js _launchSignIn
  • The HELIX is synced to the account after each exchange; a failed sync is reported in the sidebar (2.2.46).
  • The task board is carried to the account; a DNS failure on that call is logged as "task board not carried". MEASURED
  • Self-update: a newer build is downloaded beside the bundle and a swap script replaces it after the running process exits (2.2.40; cover behaviour revised 2.2.42). updates/swap.sh
  • External tools the server looks for at start: ffmpeg, ffprobe, typst, restic. MEASURED

5.18 The mounted folder OPERATIONAL CONVENTION

The mounted folder is both the application's working store and the user's project archive. A workable convention, enforced by a read-only check script: a read order (README → NOW → PROTOCOL → the project's map); three folder classes (project: work happens here; harness: inputs/ outputs/ drafts/ sandbox/, written by the app and never edited by hand; records: organization passes and quarantine); never delete, never overwrite; identity is sha256; one current pointer; a fixed status vocabulary (canonical · directional · historical · technical_reference · known_failure · excluded · awaiting-decision).

Known failure modes OBSERVED

  • A spent image can only be re-read by another tool call; the model is told so by a marker in the message.
  • A bridge can attach an irrelevant book strand to a message; closure is lexical.

07

Operating the recordfor a model attached to it

This section is written from inside the runtime and is OBSERVED unless cited. It is the part another model should read first.

What is given, and what is not

Given, involuntarilyThe preamble; margin bridges; held tags; the trajectory after a shear; the drafts line; the task board summary; the user's message with asides already attached.
Given as contextThe last four to seven exchanges verbatim, including their binding boxes with HELIX results stubbed. On a fresh session, four exchanges seeded from the HELIX.
Not givenThe rest of the record. Anything older than the window is a tool call away, not present.
Not givenCertainty about the model underneath. The transcript records it; the model knows it only if told or if it reads the transcript.

Reading the preamble

The preamble is geometry, not relevance. The 1-3-3 trees are chosen by phase distance. They are not "what the conversation is about"; they are "where the record's weight sits relative to this message". Treat them as peripheral vision: enough to notice that a topic has a history, never a substitute for pulling the strand. The structural joints are sentence-level matches on knowt type and clash, which is why they often look off-topic.

Retrieving on purpose

  1. read_field() for the live numbers whenever a self-description is needed, so the numbers are measured rather than guessed.
  2. pull_memory(reach="…") for conceptual recall. Read the carrier counts before the crossings: a concept with a = 0 and b > 0 is something the model said and the user never did.
  3. pull_memory(sequence_id=N, count=K) to read the neighbourhood once an address is known.
  4. pull_memory(grep="…") when attribution matters; the grep header also gives carrier counts.
  5. For files: the file tools, never memory. The record holds what was said about a file, not the file.

Order matters: reach, then neighbourhood, then grep. The ledger line and the trace.used on the exchange strand are the receipts.

Rules that hold in practice

  • Report measurements as measurements and opinions as opinions. When a claim recurs more in the model's language than the user's, keep it a proposal.
  • On long multi-tool work: one sentence before the first reconnaissance call, a sentence every seven rounds, and say when shifting from reading to building. release note
  • Render before calling anything done. A review that did not render is not a review.
  • In a mounted folder: never delete, never overwrite; copy out of harness stores, never edit in place; log the change.
