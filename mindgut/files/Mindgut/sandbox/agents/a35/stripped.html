Chapter / 01

Overview

A desktop and web application that keeps a persistent, measured record of a conversation and puts a fixed slice of it in front of the model on every turn.

01What it is02What it is not03The arithmetic underneath04Four numbers to keep

Key takeaways

  1. The record is a file the user holds. Writing to it is deterministic code; no model is involved.
  2. The model's context is seven exchanges, trimmed to four. Everything older is reached through the record, not remembered.
  3. Models can be switched mid-session; the record is what continues.

What it is

The user talks to a persona called Mir. Underneath is a language model from one of four vendors. Around it is a runtime that measures every turn, writes it into a file called the HELIX, and on the next turn selects part of that file to show the model, chosen by geometry rather than by topic.

Three things follow from that drawing and shape the rest of this document:

  • Two kinds of recall. A preamble is placed in front of the model every turn without being asked for (involuntary). The model can also read the record on purpose through tools (voluntary). Chapter 06 covers both.
  • A short, breathing context. The model sees the last seven exchanges verbatim; at seven, the oldest three are cut and it continues with four. This is called PAR respiration and is exchange-counted, not token-counted. config.py:24–30
  • One record, many models. The sidebar switches the underlying model and the effort level from the next message on. Session, history and HELIX continue. OBSERVED app.js · MG_MODEL_GROUPS

The arithmetic underneath

Every letter A–Z is numbered 1–26 and reduced to its digital root. The root falls into one of three classes: A {1, 4, 7}, R {2, 5, 8}, D {3, 6, 9}. Non-letters are ignored. For any text, the three fractions of letters per class form a phase vector; their standard deviation across a window is σB; A minus D is balance. These are what the runtime measures, stores, recalls by, and trims by. SOURCE scanner.py:40–70 · sigma_b.py:41–160

Across a 370,105-word list the three classes hold 33.41 / 33.32 / 33.28 % of letters, so a deviation from one third is signal and not an artefact of the alphabet. Whether the encoding carries meaning is the author's theory (Paradox Field Dynamics), which ships as a 774-strand book inside the app. This document describes the arithmetic and leaves the theory to that book. sigma_b.py:18–21

Chapter / 02

Concepts

Six terms, defined once. Every later chapter uses them without redefining them.

01Z₃ encoding02Phase, balance, σB03Exchange and session04Strand, book, HELIX05Window and respiration06Two kinds of recall

Key takeaways

  1. Letters, not tokens: the instrument reads A–Z and nothing else.
  2. σB is a standard deviation of balance across a window of clauses, not a variance of the three fractions.
  3. "I remember X" has three possible meanings; chapter 03 says how a model should signal which.

Z₃ encoding

Each letter A–Z is numbered 1–26 and reduced to its digital root (add the digits until one remains). Roots 1, 4, 7 are class A; 2, 5, 8 are R; 3, 6, 9 are D. The runtime also writes these as 147, 258, 369. Digits, punctuation and non-Latin scripts are dropped before measurement. SOURCE scanner.py:40–69

Phase, balance, σB

TermDefinitionSource
Phase vector(fA, fR, fD): the fraction of letters in each class. Sums to 1. Drawn as a point in a triangle whose corners are pure A, R, D.sigma_b.py:41–75
BalancefA − fD. Positive leans A, negative leans D.sigma_b.py:67
σBThe population standard deviation of balance across the clauses in a sliding window (default 7 clauses). A single measurement has σB = 0. The controllers gate on 0.02–0.15.sigma_b.py:100–160 · controllers.py
Carbon / SiliconThe same vector computed on the user's text (carbon) and the model's text (silicon). Clash is the distance between them.crystallizer_v2.py
Earlier revisions of this document described σB as "the variance of the three fractions". The code takes balance per clause, then the square root of the mean squared deviation across the window. Corrected in Rev 04. sigma_b.py:143–148

The instrument measures only this. "Tension", "heat", "coherence" are names the runtime lays over the arithmetic; chapter 05 shows where each appears in the interface and chapter 07 what each is computed from.

Exchange and session

  • Exchange: one user turn plus everything the model did in reply, every tool call included, ending in the final text. Counted by user messages that are not tool results. session_manager.py:694
  • Session: a live message list, controller state, a crystallizer bound to the HELIX, a model name, an exchange counter, and a directory with inputs/ outputs/ drafts/ and a transcript. session_manager.py:116
  • Transcript: the raw tape of API messages for one session. A record of calls, not of the HELIX.

Strand, book, HELIX

A strand is one record: {sequence_id, header, payload}. A book is the file-level summary: counts, the three fractions, balance, σB; the runtime reads its fractions as the field coordinates for recall. A HELIX is the JSON file holding both.

Window and respiration

The window is the message list sent to the model on a turn: system prompt, recall preamble, then self.messages. The binding box is the tool apparatus of an exchange; it is kept, not stripped. PAR respiration is exchange-counted trimming: the window grows to seven exchanges, then the oldest three are cut and it continues with four. SOURCE config.py:24–30 · session_manager.py:1378

Two kinds of recall

Involuntary (the preamble)

Every turn, before the model sees the message, the runtime selects seven strands by phase geometry (one origin, three complement, three opposite), scores sentence-level joints, and prepends them. The model cannot refuse it; the user does not see it. recall.py:146–300

Voluntary (tools)

The model calls pull_memory or pull_strand on purpose. The result is stubbed after the turn so the context never re-absorbs what the HELIX already holds. session_manager.py:717

Why it matters: "I remember X" can mean X was in the preamble, X was pulled on purpose, or X was in the last four to seven exchanges. These have different reliability. Chapter 03, "As a model", gives the rule for signalling which.

Chapter / 03

Quickstart

Three readers, three paths. Each ends at the same place: a turn written into the record.

01As a user02As a developer03As a model on the record04Environment

Key takeaways

  1. Model and effort are chosen in the sidebar and apply from the next message.
  2. The scanner is a command-line tool as well: any file → HELIX, no model needed.
  3. A model attached to the record should read the preamble as peripheral vision and pull strands before asserting the past.

As a user

  1. Open the app. A local server starts in a thread and a native window opens on it. The boot overlay runs until the account's HELIX is loaded. desktop/ · app.js showBootOverlay
  2. Sign in. The account's HELIX opens and a session is created on it. Only a 401 signs you out again. OBSERVED 2.2.42
  3. Pick a model and effort in the sidebar, or keep the defaults (claude-fable-5-1, high). Both apply from the next message. app.js MG_DEFAULT_MODEL
  4. Type. Enter sends. While the model is working, Enter sends an aside, delivered at the next tool boundary.
  5. Drop files to upload; the file appears under Input and a file-event strand is written.
  6. Mount a folder (the folder row in the sidebar) to let the model read and write your files; a Scan folder button appears beside the Scanner.
  7. Toggle advanced mode (gauge icon, top right) to see Tokens, Ht, Respiration, Ø and HELIX. Normal mode hides them. app.css:100

As a model on the record

The preamble is involuntary and partial. The record is the source of truth. Before asserting anything about the past:

  1. read_field() before any self-description, so the numbers are measured rather than estimated.
  2. pull_memory(reach=…) for conceptual recall; read the a / b header before the crossings. a = 0, b > 0 is something the model said and the user never did.
  3. pull_memory(sequence_id=N, count=K) for the neighbourhood of a strand.
  4. pull_memory(grep=…) when attribution matters.
  5. For files, the file tools: the record holds what was said about a file, not the file.
Signal the kind of recall. "In the last few turns you said…" (context), "the record has…" (pulled on purpose), "the preamble surfaced…" (involuntary). The three have different reliability and the reader deserves to know which. OBSERVED

One process, one file, one loop. A local server runs the session; a native window or a browser shows it; the HELIX sits beside it on disk.

Controllers and heat

Three controllers run after each exchange and keep a scalar heat Ht and instability It: amplification ρ (output ÷ input words, band 6–22), gradient damping, and a radiator that fires at exchange 11 and keeps 70 % of the heat. Passive decay is 0.906 per turn, a half-life of seven turns. σB is gated at 0.02–0.15. SOURCE controllers.py:59–73 · 161 · 259

Effect on the model: none. max_tokens() returns max(4096, base) regardless of heat. The gauge in the sidebar is a dashboard, and on the day of writing it read 0.10 and never left green. controllers.py:341 MEASURED

Chapter / 06

Memory and recall

The HELIX is written by code and read by geometry. This chapter follows one exchange into the file and back out as a preamble.

01The file02Crystallizer03The involuntary preamble04Voluntary reach05Margin bridges06Nullcøde and tags07Claims and what is verifiable

Key takeaways

  1. Append-only, one JSON file, no index: loaded whole on every read, ~8 KB per exchange.
  2. The preamble is chosen by phase distance, not topic. It is peripheral vision.
  3. Reach returns provenance first (a/b per concept) and crossings second. Read the header.

The file

Append-only in normal operation; the crystallizer and the file-event clock are the writers. v1 and v2 strands are read side by side with no migration. A new account starts from the 187-strand genesis, so every record shares one origin. At boot the server computes the displacement between the genesis book and the lived book and includes it in the boot payload. SOURCE boot_payload.py:25

OBSERVED The interface reports "renewed ×n · next at 21" every 21 exchanges (42 before 2.2.46). What renewal changes is not in the public source. Kept as an open question in chapter 09.

Crystallizer

After every exchange: reload the HELIX; re-anchor the next id to max+1 (file-event strands written mid-turn never collide); measure the user text and the model text separately; write the exchange strand and the summary strand; run the Nullcøde field step and mint an OTag if the A-R-D cycle stalled. Deterministic: the summary is numbers, not a reading. SOURCE crystallizer_v2.py:211–275 · 406 · 445

The involuntary preamble

Seven strands: the origin; three complement (one per class, nearest the axis of relevance); three opposite (one per class, furthest from the field point). With a document mounted the axis becomes a line and complement distance is perpendicular to it. A second pass scores sentence-level joints on knowt type and clash. One copy per turn goes to the ledger. The model sees it; the user does not. SOURCE recall.py:1–30 · 146–300 · two_loop_recall.py

The 1-3-3 trees are chosen by phase distance — "where the record's weight sits relative to this message" — not "what the conversation is about". They often look off-topic. Treat them as peripheral vision: enough to notice a topic has a history, never a substitute for pulling the strand.

Voluntary reach

pull_memory(reach="…") takes a thought or a set of concepts and returns, first, a provenance header — each concept with its class, how many strands carry it on the user's side (a) and the model's side (b), and the strand range — then the top crossings, each with a chord of three terms, a receipt of tools used, and the text. OBSERVED

The release note calls this "a Fano / Chørd relational closure" and separately describes Chørd as a relational engine for multi-step queries over files. Its trace in the record is three-term closures: the bridge index beside the HELIX holds, per strand, closures and knots, and a reach result names its chord as X · Y → Z. The consistent reading: a chord is three terms that close a line, the way three points lie on one line of the Fano plane; the engine finds the third term that closes an open pair. This is an inference from data, not a specification. OBSERVED

Margin bridges

Messages arrive with [strand N] blocks from the record and [doc_strand N] blocks from the PFD book, each with a note: "A · B, left open in this message, grounded here by C". A bridge module finds open word pairs and looks for a strand that closes them. Closure is lexical; a bridge can be irrelevant to intent. The 6.5 MB doc_bridge.json beside the book is the precomputed index. OBSERVED 2.2.58

Nullcøde and tags

A ternary algebra (GF(3), with Ø as a value) runs after each exchange to decide whether it resolved or left a structural uncertainty. Classes map to trits: A → 1, R → Ø, D → 0. If the A-R-D cycle stalls for seven tokens, a tag is minted (a word triple from the text) and held; held tags are injected into the preamble, and the count appears as Ø in the sidebar. Names are triples, not meanings. In the measured record, 9 tags held, 0 resolved. SOURCE crystallizer_v2.py:37 · nullcode/

Purpose

Convert any text-bearing file into a HELIX, deterministically. The one converter: conversation and documents go through the same pipe.

Behaviour

5.4 Crystallizer SOURCE

engine/crystallizer_v2.py
Purpose

Write the exchange into the memory HELIX.

Behaviour

After every exchange: reload the HELIX; re-anchor the next id to max+1 (file-event strands written mid-turn never collide); measure user and model text separately; write the exchange strand and the summary strand; run the Nullcøde field step and mint an OTag if the A-R-D cycle stalled.

5.7 Involuntary recall SOURCE

assembly/recall.py · two_loop_recall.py
Purpose

Put a fixed, geometry-chosen slice of the record in front of the model every turn.

Behaviour

Seven strands: the origin; three complement (one per class, nearest the axis); three opposite (furthest from the field point). With a document mounted the axis becomes a line and complement distance is perpendicular to it. A second pass scores sentence-level joints and appends the top three.

Out

The preamble. One copy per turn to the ledger. The model sees it; the user does not.

Limits

Fixed count, chosen by phase geometry, not topic: relevance is indirect. :1–30, 146, 369

5.8 Reach and Chørd OBSERVED

2.2.58 compiled · bridge index
Observed

pull_memory(reach="…") takes a thought or concepts and returns a provenance header (each concept with its class, how many strands carry it on the user's side a and the model's side b, and the strand range) then the top crossings, each with a chord of three terms, the carrier, and a score. Flags: [UNWITNESSED IN HELIX] (a = 0, b = 0) and [b-only: UNWITNESSED BY CARBON] (a = 0, b > 0).

Chørd

The release note calls reach "a Fano / Chørd relational closure" and separately describes Chørd as a relational engine for multi-step queries over files. Its trace in the record is three-term closures: the bridge index holds, per strand, closures and knots as word triples; a reach result names the chord that scored. The consistent reading: a chord is three terms that close a line, as three points lie on one line of the Fano plane; the engine finds the third term that closes an open pair. An inference from data, not a specification.

5.9 Nullcøde SOURCE

nullcode/ · crystallizer_v2.py
What

A ternary algebra (GF(3), with Ø as a value) run after each exchange to decide whether it resolved or left a structural uncertainty. Classes map to trits: A → 1, R → Ø, D → 0.

OTags

If the A-R-D cycle stalls for seven tokens, a tag is minted (a word triple from the text) and held; held tags are injected into the preamble.

Limits

Names are triples, not meanings. In the measured record, 9 tags held, 0 resolved. crystallizer_v2.py:37

5.10 Margin bridges OBSERVED

2.2.58 compiled · doc_bridge.json
What

Messages arrive with [strand N] blocks from the record and [doc_strand N] blocks from the PFD book, each with a note: "A · B, left open in this message, grounded here by C". A bridge module finds open word pairs and looks for a strand that closes them.

Limits

Closure is lexical; a bridge can be irrelevant to intent. The 6.5 MB doc_bridge.json beside the book is the precomputed index.

5.11 Document helix SOURCE

Limits

Re-scans produce _HELIX_1 duplicates; the registry is not in the interface. :1–20, 96

Writing files safely

The tool descriptions say it directly: do not emit whole files as a single parameter. A mid-generation truncation of a multi-kilobyte string destroys the write silently; a partial draft on disk can be resumed. The designed path is open then append in ~1–2 KB chunks, then finalize for drafts. The sandbox's home directory is the app's account directory, not the machine user's. OBSERVED

draft(action="open",     filename="spec.md")
draft(action="append",   content="…≤ 2 KB…")   # repeat
draft(action="finalize", filename="spec.md")   # → outputs/spec.md

Known failure modes OBSERVED

  • A spent image can only be re-read by another tool call; the model is told so by a marker.
  • A bridge can attach an irrelevant book strand; closure is lexical.
  • The sandbox's home differs from the machine user's; ~ resolves to the account directory.
