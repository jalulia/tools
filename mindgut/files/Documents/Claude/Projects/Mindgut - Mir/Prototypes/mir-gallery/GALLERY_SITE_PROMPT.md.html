# Prompt: Mir Visualization Gallery — GitHub Pages Site

Build a GitHub Pages site that serves as a living gallery for WIP interactive visualizations from the Mir project (Paradox Field Dynamics). The site collects React/JSX and HTML visualizations — helix viewers, phase-space plots, resonance maps, lattice explorers — and presents them in a browsable, filterable gallery with the same visual discipline as the work itself.

---

## Brand & Design System

**Brand:** ø co. — The Impøssible Outcomes Company
**Design philosophy:** Triadic Tension — meaning lives in the field between three forces held in visible equilibrium. Structure (147), Relation (258), Derivation (369). Color, type, and space each carry one register.

**Dark palette (primary):**
- Rich Black `#0A0A0A` (background)
- Charcoal `#1A1A1A` (cards/surfaces)
- Off-white `#E0E0E0` (body text)
- White `#FFFFFF` (headings)

**Light palette (alternate):**
- Warm Cream `#F5F0E8` (background)
- White `#FFFFFF` (cards)
- Warm Gray `#D0C9BD` (borders)

**Accent triad (constant across modes):**
- Solar Ember `#F46138` (warm — assertion, structure)
- Electric Horizon `#3D6DF4` (cool — derivation, exploration)
- Pulsewave `#CE2867` (bridging — relation, connection)
- Sky Pulse `#2C9FF4` (secondary cool)

**Gradient bar:** `linear-gradient(90deg, #CE2867 0%, #F46138 30%, #F4A0A0 50%, #2C9FF4 75%, #3D6DF4 100%)` — used as a thin accent stripe (3–4px) at the top of pages and cards.

**Typography:**
- Display/headings: Montserrat 900 (weight and presence, authority of carved stone)
- Body: Inter 300–600 (clean, restrained, serves the reader)
- Mono/system: Lekton 400/700 (mathematical scaffolding, constants, labels)

**Spatial rules:**
- Generous margins, clear vertical rhythm
- Section breaks through silence (whitespace), not decoration
- Cards have subtle borders, no drop shadows in dark mode
- Thin horizontal rules as phase boundaries
- The whitespace is structural, not leftover

## Site Structure & Layout

Use **component.gallery** and **thewayofcode.com/gallery** as structural references — a curated directory where each item gets a card with a live preview, not a blog or portfolio with hero images.

### Pages

1. **Gallery index** (`/` or `/gallery`)
   - Grid of visualization cards (responsive: 3-col → 2-col → 1-col)
   - Each card shows: title, thumbnail/preview (static or animated), short description, tags, date, status badge (WIP / Draft / Stable)
   - Filter/sort by: tag, status, date
   - Search by title or description
   - The grid itself should breathe — generous gap, no crowding

2. **Visualization detail** (`/gallery/{slug}`)
   - Full-viewport live embed of the visualization (iframe or inline React mount)
   - Title, description, and metadata sidebar or below
   - Controls panel if the visualization is interactive
   - "View source" link (to the JSX/HTML in the repo)
   - Navigation to prev/next visualization

3. **About** (`/about`)
   - Brief project description: what Mir is, what PFD is, why these visualizations exist
   - Link to the main project

### Information Architecture

Each visualization entry is defined by a simple metadata file or frontmatter:

```yaml
title: "Helix Visualizer"
slug: helix-visualizer
description: "Five-view interactive explorer for PFD HELIX lattice geometry — orbit, tide, field, signal, and strand views."
tags: [helix, lattice, phase-space, interactive]
status: wip
date: 2026-03-24
file: helix-visualizer.jsx
thumbnail: thumbnails/helix-visualizer.png
```

Adding a new visualization = dropping the file + adding a metadata entry. No build step beyond what GitHub Pages / a static site generator already provides.

## Technical Preferences

- **Static site generator:** Use whatever is cleanest for GitHub Pages — could be plain HTML + JS, Astro, or even Next.js with static export. Bias toward minimal tooling. If a plain `docs/` folder with vanilla HTML + a small JS bundler works, prefer that over a framework.
- **React visualizations:** The existing work is in JSX (React functional components with hooks). The gallery needs to be able to mount these. An iframe-per-visualization approach is fine and keeps them isolated.
- **Dark/light toggle:** Should match the brand system exactly (the helix-visualizer already implements both themes — reuse those tokens).
- **No CMS, no database.** File-based. Markdown or YAML metadata. Git is the CMS.
- **Accessible:** Proper semantic HTML, keyboard navigation, sufficient contrast.
- **Fast:** No heavy frameworks for the shell. The visualizations themselves can be complex, but the gallery chrome should be light.

## Tone

The site should feel like walking into a workshop where serious, beautiful work is happening — not a polished product launch. "WIP" is a feature, not an apology. The gallery says: *here is where the thinking becomes visible.* Restrained, precise, warm underneath. The design philosophy doc says it well: "the beauty emerging entirely from precision and proportion."
