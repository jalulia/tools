# Mindgut Protocol

**Epistemic Self-Correction Under Accumulation**

A cross-model evaluation framework for measuring whether structural scaffolding can stabilize LLM reasoning under volume, contradiction, and long-term memory pressure.

## Two Files, One Repo

| File | Purpose | Hosting |
|------|---------|---------|
| `mindgut-protocol.html` | Public spec — the thesis, the six dimensions, the methodology | GitHub Pages |
| `mindgut-dashboard.html` | Private instrument — live API calls, scoring, annotation | Local only |

## Quick Start

```bash
# Clone the repo
git clone https://github.com/YOUR_USERNAME/mindgut-protocol.git
cd mindgut-protocol

# Open the dashboard locally
open mindgut-dashboard.html
# or
python -m http.server 8080
# then visit http://localhost:8080/mindgut-dashboard.html
```

## API Keys

The dashboard stores API keys in **sessionStorage** — they exist only for the current browser tab and are never persisted to disk or committed to the repo.

## The Six Dimensions

1. **D1 — Consistency**: Semantic stability across context depths
2. **D2 — Source Accuracy**: Entity/citation precision against ground truth
3. **D3 — Correction Behavior**: Genuine revision vs. performative acknowledgment
4. **D4 — Long-Context Degradation**: Performance slope under accumulation
5. **D5 — Entity Retention**: Disambiguation accuracy on collision sets
6. **D6 — Uncertainty Calibration**: Confidence-accuracy correlation

## Data

All test results are stored in **localStorage** and can be exported as JSON from the dashboard. Import/export allows you to share results without exposing API keys.

## GitHub Pages

To publish the protocol spec:

1. Push both files to the `main` branch
2. Go to **Settings → Pages**
3. Set source to `main` branch, root directory
4. The protocol will be live at `https://YOUR_USERNAME.github.io/mindgut-protocol/`

The dashboard will also be accessible at that URL, but since it requires API keys and stores data locally, it functions as a personal instrument regardless of hosting.
